With AVX-512, if-conversion correctly produces .COND_FMA, but cond_fma<mode> in config/i386/sse.md expands it as an unmasked fma into a temporary followed by a vec_merge with the else value. The multiply-add is therefore evaluated in lanes whose condition is false, and raises FP exceptions the source never performs, under the default -ftrapping-math. cond_fms, cond_fnma and cond_fnms have the same shape. The expanders are unchanged on master.

Testcase (the preprocessed file from gcc 13.3.0 -save-temps is attached):

/* Masked-off lanes of an if-converted FMA raise FP exceptions.
   The x86 cond_fma expander emits an unmasked FMA and a blend, so the
   multiply-add runs on lanes where m[i] == 0, which the source never
   computes.  Under the default -ftrapping-math that is wrong code:
   FE_OVERFLOW is set (and SIGFPE is raised with traps enabled).  */

#define _GNU_SOURCE
#include <fenv.h>
#include <stdio.h>
#include <stdlib.h>

#define N 64

__attribute__((noipa)) void
f (double *restrict a, const double *restrict b, double *restrict c,
   const int *restrict m, double w, double e, int n)
{
  for (int i = 0; i < n; i++)
    {
      c[i] = b[i];		/* b[i] is loaded in every lane */
      if (m[i])
	a[i] = a[i] + b[i] * w;
      else
	a[i] = e;
    }
}

int
main (int argc, char **argv)
{
  static double a[N], b[N], c[N];
  static int m[N];
  (void) argv;
  for (int i = 0; i < N; i++)
    {
      m[i] = i & 1;
      b[i] = m[i] ? 1.0 : 1e307;	/* 1e307 * 1800 overflows */
    }
  if (argc > 1)
    feenableexcept (FE_OVERFLOW);
  feclearexcept (FE_ALL_EXCEPT);
  f (a, b, c, m, 1800.0, -1e34, N);
  if (fetestexcept (FE_OVERFLOW))
    {
      puts ("FAIL: FE_OVERFLOW from a masked-off lane");
      fflush (stdout);
      abort ();
    }
  puts ("PASS");
  return 0;
}

b[i] * w overflows only where m[i] == 0, where the source assigns e and never computes the product.

Generated code, an unmasked FMA then a blend:

  vfmadd213pd   (%rdi,%rax,2), %zmm4, %zmm2
  vpcmpd        $4, %zmm6, %zmm7, %k1
  vblendmpd     %zmm2, %zmm3, %zmm2{%k1}

With -ffp-contract=off the same loop uses .COND_MUL/.COND_ADD, which expand masked (vmulpd ...{%k1}{z}, vaddpd ...{%k1}), and passes. AVX-512 masking suppresses exceptions in masked-off elements, so a zero-masked FMA (fma_fmadd_<mode>_maskz_1) followed by the merge with operand 5, or a merge-masked form when operand 5 is one of the inputs, would avoid this.

Found in the wild: the masked time-averaging loop in NOAA-GFDL FMS diag_manager.F90 (if (mask) buffer = buffer + field*weight, else buffer = missvalue), built -O3 -march=icelake-client and linked into an executable compiled with -ffpe-trap=overflow. There the field is a merge-masked load, so the masked-off lanes hold stale register contents and the SIGFPE is intermittent.
