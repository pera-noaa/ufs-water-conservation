@fmahebert @MarekWlasak Thanks. For H(x) the OOPS option does the same job (its test, `hofx_tinterp.yaml`, is H(x) only). The linearized observer is still nearest-state: `GetValues` widens the window for linear interpolation only in the nonlinear path ([L395](https://github.com/JCSDA/oops/blob/ef934f23f10187653a7cb7e9024dec9bca29716c/src/oops/base/GetValues.h#L395)), while `processTL` and `processAD` keep `halfWidth_ = tstep/2` ([L628](https://github.com/JCSDA/oops/blob/ef934f23f10187653a7cb7e9024dec9bca29716c/src/oops/base/GetValues.h#L628), [L805](https://github.com/JCSDA/oops/blob/ef934f23f10187653a7cb7e9024dec9bca29716c/src/oops/base/GetValues.h#L805)). So a 4D-Var with `time interpolation: linear` gets an interpolated H(x) with a nearest-state TL and adjoint; `TimeOperLinInterp` is consistent in all three. Once the OOPS TL/AD interpolate, the operator is redundant and I'd be glad to see it retired. Until then, this PR stops it from silently returning nearest-state H(x).
